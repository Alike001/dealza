## Root cause and implementation

Both wallet order discovery and per-order activity called the same `rawLogs` function. It requested **1,000 inclusive blocks** even though the configured official Base Sepolia RPC accepts at most **200**. Each view also scanned a 10,000-block window; order polling could repeat that whole history scan every 15 seconds. Older-page requests did not protect against an intervening account/network change.

Every production frontend event query now passes through `eventLogs.ts` and the single `eth_getLogs` call in `chainGateway.ts`. The other log queries under `web/scripts/` are historical verification utilities, not imported production frontend paths; they were inventoried and retained unchanged.

- `VITE_RPC_LOG_BLOCKS`: default **200**, accepts integer **1–200**; invalid configuration fails explicitly. Providers with lower limits can be configured before building. Explicit range/result-size errors also halve the working range and retain that learned smaller limit for the current reader.
- `VITE_HISTORY_BLOCKS`: default **2,000**, accepts integer **1–10,000**. This is the logical UI window, separate from the maximum RPC range. A typical activity page makes 10 operator + 10 CPP requests at the default settings, rather than 100 requests for the former 10,000-block window.
- Inclusive ranges use `end = start + size - 1`, `start = end + 1`; the older cursor is `from - 1`. The deployment record fixes the lower bound at **53676176**, never genesis. Initial pages end one block behind the observed head; this is a confirmation cushion, not an L1-finality claim.
- A shared reader serializes log requests with at least 100ms pacing. Transport retries are disabled for log requests so retries are not multiplied. Transient errors retry at most twice with 500ms/1s backoff. Range reduction has a finite lower bound of one block, after which the error is surfaced.
- Pages commit atomically. Invalid, unconfirmed, conflicting, out-of-range or non-array responses fail the page; a later failed chunk never advances the cursor. Existing successful pages stay visible with an explicit incomplete-history error and retry button.
- Logs sort by block and log index and deduplicate by transaction hash + log index. UI pages retain that order, merge without duplicate records and use stable activity keys. Discovery deduplicates order IDs.
- AbortSignals stop queued/subsequent work, and aborted in-flight results cannot update a new account/network/order scope. An already-started HTTP read can finish within its timeout; no signing or state mutation is involved.
- History has explicit initial loading, empty-window, older-page, retry, refresh and deployment-bound end states. It labels recent windows as incomplete until earlier blocks are checked. Empty recent windows never claim that the wallet has no historical orders.
- The 15-second current-state poll remains. History windows refresh on explicit request, account/network change or a successful application action, rather than re-reading a window on every poll. Explicit refresh starts a fresh recent window; users can load older pages again.
- Order-list labels come from current verified `loadOrder`/CPP financial state, even when the creation event is old. Current status is not inferred from `OrderCreated`. EIP-7702 creation/receipt checks and fund-moving code were preserved. No indexer/backend was added.

Standard `eth_getLogs` does not carry a total count: a provider silently returning a valid-looking subset cannot be detected from that response alone. The actual known payment events were therefore independently compared against previously verified canonical receipt identities. This is distinct from malformed/explicitly partial responses, which the reader rejects.

## Repository preservation and reproduction

Earlier README/source-verification changes, report 13, untracked preparation scripts and prior evidence remain outside the focused checkpoint commits. No private key or environment credential was introduced; the final heuristic scan is recorded separately. `VITE_` configuration values are public browser settings.

```sh
npm test
npm run build
npm run dev
# Alternatively, serve web/dist:
npm run preview --workspace web
cd contracts
forge test
FOUNDRY_PROFILE=fork forge test
python3 scripts/verify_protocol.py
python3 scripts/verify_protocol.py --online
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Default pages use the official RPC, `VITE_RPC_LOG_BLOCKS=200`, `VITE_HISTORY_BLOCKS=2000`. Configure smaller values for stricter providers and rebuild. A failed page must be retried; it must not be treated as end-of-history. Browser read-only evidence was obtained through the actual production UI and development gateway, never through invented RPC responses.
